D36: **D35 was written from the package's README, not its bytes — four corrections, made on first contact with the actual source.** All four were found by downloading `@bryllim/workout-guide@1.0.0` and opening it, before any code was written. The decision to use it SURVIVES; the details were wrong:

1. **They are PNG, not SVG.** D35 and the T2-F spec both say "3 transparent 512×512 SVG frames". The package ships **PNG** (`manifest.json` → every frame `"format": "png"`, 34.4 MB unpacked). There is no SVG in it. Consequence: `media_type` is `'figure-sequence'`, NOT `'svg-sequence'` — the kind names the PLAYBACK MODEL (a directory of `frame-N.png`), so re-drawing the frames as SVG later needs no migration.
2. **The art is WHITE on transparent — invisible on this app.** It is drawn for dark UIs. On Marcus's warm-white theme it renders as nothing at all. It is therefore recoloured with `filter: invert(1)` **in the browser** (`.figure-seq__frame`, globals.css). This is the narrow path through D35's hard rule: the file on disk and on the wire is **byte-identical**, so no Adapted Material is ever DISTRIBUTED and ShareAlike never attaches to the app's own source. D35 called a container recolour "still risky" — a CSS filter at display time is the safer form of that idea, and `MediaCredits` discloses it ("Shown recoloured … the artwork files are unmodified"), which satisfies CC-BY-SA § 3(a)(1)(B)'s indicate-if-changed limb even on a conservative reading. **Still forbidden: pre-processing the PNGs on disk.**
3. **The upstream is Everkinetic, and it was evaluated head-to-head.** `ATTRIBUTION.md` discloses that 76 first-pose frames are adaptations of [everkinetic/data](https://github.com/everkinetic/data) (also CC-BY-SA-4.0) — which _does_ ship real SVGs, 289 exercises × 2 frames. It covers **34/83** of Marcus's library against workout-guide's 76/83. Real SVG lost to real coverage. Everkinetic is credited in `MediaCredits` regardless, because its art is in there.
4. **830 of the 906 frames carry no upstream attribution** — claimed as original by one maintainer in a package published 2026-08-24. Not a blocker (the licence grant is on its face valid and the art is visually consistent), but it is the same _class_ of unverifiable chain-of-title that D35's traps section exists to flag.
