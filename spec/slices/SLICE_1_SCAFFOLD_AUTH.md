# SLICE_1_SCAFFOLD_AUTH.md

## 1. Goal
Stand up the Next.js + Supabase + Tailwind + shadcn project with magic-link
authentication, automatic profile creation on first login, and a bottom-tab-
bar app shell that renders empty placeholder pages for all five tabs.

## 2. Acceptance Criteria

1. Running `pnpm dev` from the project root starts the Next.js dev server on
   localhost:3000 with no errors and no warnings beyond the standard
   Next.js startup output.
2. Visiting localhost:3000 while not logged in redirects to /login.
3. The /login page renders a single email input + "Send magic link" button,
   styled with the dark theme and lilac accent.
4. Submitting an email triggers a Supabase magic-link send and shows a
   "Check your email — link sent to <email>" confirmation state.
5. Clicking the magic link in email lands on /auth/callback, exchanges the
   code for a session, and redirects to /today.
6. On first successful login, a row is inserted into the `profiles` table
   with the user's auth.uid() as user_id, goal_mode='maintain', and null
   bodyweight_kg and height_cm.
7. On subsequent logins, the existing profile row is reused — no duplicate
   inserts, no overwrites of bodyweight/height/goal_mode.
8. The authenticated app shell renders a bottom tab bar with five tabs:
   Today, Plan, History, Nutrition, Settings. Each tab is a clickable link
   to its route.
9. The five tab pages (/today, /plan, /history, /nutrition, /settings)
   render an empty page with the tab name as a heading and the bottom tab
   bar visible. The active tab is visually distinguished (lilac accent).
10. Logging out (via a Settings → Sign out button) clears the session and
    redirects to /login.
11. Visiting /today, /plan, /history, /nutrition, or /settings while
    unauthenticated redirects to /login.
12. The dark theme is applied globally: pure black background, white text,
    lilac accent CSS variable available as Tailwind utility classes.
13. shadcn/ui is configured. The Button primitive is installed and used on
    the login form.
14. ESLint and Prettier run cleanly on the entire codebase
    (`pnpm lint` and `pnpm format:check` both pass).
15. TypeScript strict mode is on (`tsconfig.json` has `"strict": true`).
    `pnpm typecheck` passes with zero errors.
16. The pnpm-lock.yaml is committed to the repo. node_modules is gitignored
    and not committed.

### Migration: 001_init_auth_profile.sql
```sql
-- Idempotent. Safe to run multiple times.
CREATE TYPE goal_mode_enum AS ENUM ('cut', 'maintain', 'lean_bulk');

CREATE TABLE profiles (
  user_id        uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  display_name   text,
  bodyweight_kg  numeric,
  height_cm      numeric,
  goal_mode      goal_mode_enum NOT NULL DEFAULT 'maintain',
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER profiles_set_updated_at
  BEFORE UPDATE ON profiles
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

### Migration: 007_rls_policies.sql (profiles section only in this slice)
```sql
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "select_own" ON profiles
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "insert_own" ON profiles
  FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY "update_own" ON profiles
  FOR UPDATE USING (auth.uid() = user_id);

-- No DELETE policy. Profile rows are tied to auth.users via ON DELETE
-- CASCADE; deleting the user deletes the profile. Direct profile
-- deletion is not exposed.
```

## 5. Edge Cases to Handle

1. **User submits an invalid email format** — client-side validation
   blocks submit; show inline error "Enter a valid email address."
2. **Supabase signInWithOtp returns an error** (rate limit, invalid
   email, network failure) — show error message inline, return to idle
   state, do not advance to "sent" state.
3. **Magic link expired or already used** — auth/callback receives
   an error from exchangeCodeForSession; redirect to
   /login?error=link_expired with an inline error message on /login.
4. **First-login profile insert race condition** — ON CONFLICT
   (user_id) DO NOTHING ensures idempotency. If somehow two callbacks
   fire (unlikely but possible), neither errors.
5. **User authenticated but profile row missing** — should not happen
   if callback runs correctly, but as a defensive measure: the (app)
   layout's profile fetch returns null → redirect back to
   /auth/callback to retry profile creation. Log this case to console
   for visibility.
6. **User navigates directly to /auth/callback without a code** —
   redirect to /login.
7. **Sign out fails** (network error) — show toast/inline error,
   do not redirect. User can retry.
8. **Tab bar on a route that is not one of the five tabs** (e.g.
   /today/workout/123 in future slices) — the tab bar still highlights
   "Today" because the path starts with /today. Use startsWith matching,
   not strict equality.
9. **Cold cache on first visit** — service worker is not in this slice;
   first paint relies on Next.js streaming. No special handling needed.
